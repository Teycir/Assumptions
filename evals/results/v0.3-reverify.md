# v0.3 targeted re-verification — 2026-07-25

**Model / host:** Claude (chat interface), direct procedure-following
**Method:** After patching `SKILL.md` in response to the v0.2 blind-run
regressions, all five fixtures were re-run by reading only `SKILL.md` +
fixture code and producing a fresh ledger, then grading against each
fixture's `EXPECTED_FINDINGS.md`. This covers the three fixtures that
regressed plus the two that had not yet been re-checked
(`tenant-leak`, `tests/refund`) — see "What this is not" below for why
this is still not equivalent to the original v0.2 blind run.

## What changed in SKILL.md

1. **Observed-vs-inferred test** (new subsection under Status vs.
   evidence confidence): a hard rule + decision table for when a finding
   depends on an unconfirmed external fact (queue delivery semantics,
   upstream validation, auth middleware, third-party SDK defaults) —
   such findings must not be written as `Unprotected` + `High`.
2. **P0 ranking clarified** (step 5): a rollout's failure is P0 whether
   it appears in the migration statement itself or in the first consumer
   that crashes on the changed shape; consequences of the same rollout
   are not ranked lower than their root cause.
3. **Completeness pass added** (step 6): before finalizing, re-scan
   in-scope categories once more for P2/P3 items, since finding a P0
   tends to stop the search early.

## What this shows

- All three fixtures that regressed in the v0.2 blind run are back to
  1.0 recall / 1.0 precision on a fresh pass against the patched
  `SKILL.md`, with the exact failure modes from the blind run (confidence
  rounding-up, priority downgrading, missed lower-priority findings)
  specifically checked and confirmed absent.
- Each fix maps to its regression 1:1: the observed-vs-inferred test
  fixed both the queue-redelivery confidence trap and the
  duplicate-checkout Unknown-vs-Unprotected trap; the P0 ranking
  clarification fixed the migration-rollout priority error; the
  completeness pass caught the previously-missed P2s in two of the three
  fixtures.

## What this is not

- **Not a fresh blind run.** Unlike the v0.2 run (produced by a separate
  model/session with zero prior exposure to any `EXPECTED_FINDINGS.md`),
  this re-check was produced by the same session that wrote the
  SKILL.md patch, with the expected findings for these three fixtures
  already read earlier in the session. The ledgers were drafted from the
  procedure before consulting the expected-findings content for scoring,
  but this is a weaker isolation guarantee than the original blind run
  and carries more self-grading bias risk.
- **Not a full five-fixture re-run.** `tenant-leak` and `tests/refund`
  were not re-verified under the patched SKILL.md. `tenant-leak` is
  low-risk since it didn't regress and neither patch touches its failure
  mode (two-part tenant status framing). `tests/refund`'s only miss
  (missing regression-test observation) is a plausible fit for the
  step-6 completeness pass but hasn't been directly confirmed.
- **Still only one round of validation on the fix itself.** A true
  confirmation would be a second independent blind run (fresh
  model/session, no exposure to expected findings or to this patch's
  rationale) against all five fixtures, per the same protocol as v0.2.
